# 太乙掩、囚、格位置关系机械候选审计

本页记录 v0.41.0 在既有太乙年计框架上新增的三类位置标签：掩、囚、格。它们只是把已经算出的太乙、天目、始击和主客大小将做同宫或对宫比较，不包含卷三紧随其后的政治、军事、吉凶、成败解释，也不会生成中间信号、应期、行动建议或 Rule ID。

> 历史说明：本页固定 v0.41.0 / 关系算法 v1 的审计边界。v0.44.0 已在兼容新版本中增加无方向邻位几何和“对”位置标记，详见 `TAIYI_NEAR_RING_OPPOSITION_AUDIT.md`；本页原有档案和断言不回写。

## 三种已实现的位置定义

### 掩

卷三“推掩法”开头直接说“始击将临太乙宫谓之掩”。程序只比较始击所在十六神位置是否恰好是太乙所在正宫：

```text
始击环位置 == 太乙环位置 → shiji_covers_taiyi = true
```

“岁计遇之”以下解释没有进入代码。

### 囚

卷三“推囚法”记“若文昌将并主客大小四将俱与太乙同宫，总名曰囚”。在当前年计机械层中，文昌即天目，主客大小四将已经各有数字宫位，因此逐项比较：

- 天目与太乙同宫；
- 主大将与太乙同宫；
- 主参将与太乙同宫；
- 客大将与太乙同宫；
- 客参将与太乙同宫。

卷三“三门五将立成胜败钤”首行给出“天目武德、太乙一宫：参将囚”。阳局第一算的主参将恰在一宫，与程序的第一算结果闭合。表中的“主人小败”等胜败格没有进入实现。

### 格

卷三“推格法”开头记“客目大小将与太乙对宫为格”。程序按该句的主语范围，只检查始击（客目）、客大将、客参将，不把主方大小将擅自扩入“格”。

太乙八正宫的对宫映射固定为：

| 太乙宫 | 对宫 |
|---:|---:|
| 1 | 9 |
| 2 | 8 |
| 3 | 7 |
| 4 | 6 |
| 6 | 4 |
| 7 | 3 |
| 8 | 2 |
| 9 | 1 |

这等价于在既有十六位环上相隔八位。中五宫不属于太乙所行八宫，也不会被当作任何太乙宫的对宫。

## 明确没有顺手实现的关系

卷三同一组章节还列有击、迫、关、对、四郭固、四郭杜、执提、提挟。本版没有因为它们与三项直接定义相邻就一并实现：

- 击、迫涉及“前一辰、后一辰、前一宫、后一宫”、内外方向和上下二目的适用差异；
- 关涉及主客大小将“相宫齐”“同宫数齐”的具体口径；
- 对虽有冲当定义，但应先与格及十六位环的主体范围做独立审计；
- 四郭等是复合条件，不能由单一位置相等自动推出。

对应对象永久保存 `strike_classified = false`、`pressure_classified = false`、`barrier_classified = false`、`opposition_classified = false`。

## 历史快照与运行边界

`TaiyiAnnualFrame` 的算法版本升至 v5，并新增独立 `TaiyiMechanicalRelations`。关系字段带有反序列化缺省值：读取 v1–v4 历史快照时只得到“未计算”的空关系对象，不会用新算法静默改算旧记录。

本版仍然不能：

- 从现代公历日期选择积年历元并生成积年；
- 选择阴遁或生成完整局式；
- 生成太乙、主大将、客大将三套旋转门盘；
- 根据掩、囚、格输出吉凶、胜败、概率、总分、应期或行动建议；
- 生成正式 Rule ID 或让太乙参与综合裁决。
