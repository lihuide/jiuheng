# 古籍影印文件字节准入门禁（v0.67.0）

## v0.67.0：从字段格式升级为实际文件验证

此前 v11 门禁能拒绝伪造格式，却仍只能证明数据库里填写了一个形似 SHA-256 的字符串，不能证明软件读取过对应影印文件。SQLite v12 新增 `source_facsimile_verifications`：

- 桌面开发者模式接受已登记的 `source_id` 和本地文件路径；
- 纯 Rust `jiuheng.sha256.v1` 以 64 KiB 缓冲流式读取完整文件，不把影印内容写入数据库；
- 计算结果必须与版本书目登记的小写 `sha256:` 完全一致，且文件字节数必须大于零；
- 成功后只保存 `source_id`、校验和、字节数、文件名、验证器版本和 RFC 3339 时间；
- 正式主来源门禁要求该记录与当前版本校验和一致，手填校验和而没有实际文件验证记录不能放行；
- 验证记录参加规则证据包哈希。新增、修改、删除验证或更换版本校验和都会使旧四类复核失效；
- 升级到 v12 时旧规则的 `reviewed` 状态被撤销，必须重新绑定实际字节验证和复核。

内置正式规则包仍为空。门禁更严格不等于已经取得任何新古籍影印，也不产生 Rule ID、断语、应期或行动建议。

## v0.60.0/v11：规范校验和格式

此前 SQLite 规则准入视图只要求主来源的 `digital_checksum` 非空，`sha256:test-only` 这样的描述文字在结构上也能通过。它不能作为影印文件校验凭据。本轮 v11 数据库迁移改为要求：

- 主来源是影印、校勘或有底本的整理版本，不接受纯电子转录类型；
- 有馆藏目录号和影印定位；
- 对应原文片段有非空卷页定位及原文，且转录状态为 `verified`；
- 校验和采用严格的小写 `sha256:` 加 64 位十六进制格式；
- 当前规则证据包哈希、四类复核和自动测试仍按原有独立门禁执行。

旧数据库自动迁移到 v11。旧记录不会被删除；不满足新条件的规则立即失去发布资格，不能继续命中或参与融合。迁移不会替旧记录编造新校验和。

## 对真实影印文件的核验

`scripts/verify-source-facsimile.ps1` 接受本地影印文件、预期 `sha256:` 校验和及可选文件字节数，重新读取文件计算 SHA-256；任一不一致则报错。示例：

```powershell
pwsh -File scripts/verify-source-facsimile.ps1 -SourcePath 'path/to/page.jpg' -ExpectedChecksum 'sha256:<64 lowercase hexadecimal digits>' -ExpectedBytes 123456
```

此脚本不下载、修改或复制原始影印文件。v0.67.0 起桌面开发者模式和 Rust 存储层还会把实际读取结果绑定到数据库证据包；但文件哈希只能证明“所审字节未变”，仍不能代替卷页定位、逐字转录、异文整理和书目/转录/逻辑/实现四类复核。

## 本轮《卜筮正宗》追索结果

[Wikimedia Commons 的哈佛燕京藏本条目](https://commons.wikimedia.org/wiki/File:Harvard_drs_53238001_%E5%8D%9C%E7%AD%AE%E6%AD%A3%E5%AE%97%E5%85%A8%E6%9B%B8_v.1%E5%8F%99%E3%80%81%E7%9B%AE%E9%8C%84%E3%80%81%E5%8D%B7%E4%B9%8B%E4%B8%80%E3%80%81%E5%8D%B7%E4%B9%8B%E4%BA%8C.pdf) 记载卷一、卷二影印为 59 页、约 50 MB，绿荫堂乾隆丁未（1787）重刊本，来源关联哈佛馆藏；这些只是书目与资源元数据。本机对原始 PDF 的临时下载在 TLS 握手阶段失败，未取得文件字节，因此本轮没有新增任何《卜筮正宗》页号、哈希或已核原文声明。

六爻三合仍仅为成员与来源出现清点；三合成局、效力、应期、断语及正式 Rule ID 均保持关闭。正式规则种子继续为空。

## 2026-09-22 哈佛《卜筮正宗》影印重试

但完整原始 PDF 下载和仅取前 1 KiB 的 HTTP Range 请求都在 TLS 握手阶段超时；Harvard IIIF manifest 同时返回限流。本机仍未取得任何 PDF 字节，不能运行 PDF 页渲染、逐页定位或 SHA-256 校验。因此本轮只更新“已核资源元数据”，不登记文件哈希、不填写古籍页码、不把电子转录升级为已核原文，也不新增 Rule ID。后续只有成功取得完整原文件并按 `scripts/verify-source-facsimile.ps1` 验证后，才进入页图和转录校勘。

## 2026-09-23 v0.70.0 下载通道复核

再次从 Wikimedia Commons 当前文件页打开原始文件地址，页面元数据仍显示 59 页、52,560,168 字节、Harvard DRS 53238001、馆藏号 `T 1740 1122` 及 Public Domain Mark。Windows Schannel 下载返回 `SEC_E_NO_CREDENTIALS`，独立 OpenSSL 客户端在握手阶段超时；随后尝试浏览器正常下载通道时，本机浏览器控制组件因运行资源路径缺失而未能启动。项目目录没有产生 PDF、缩略图或不完整临时文件。

因此 v0.70.0 仍不登记影印 SHA-256、页码、逐字转录、四类复核或正式 Rule ID。此失败记录用于防止后续把已核资源元数据误写为已取得原始字节，不影响本版独立完成的六爻五行方向机械层。

## 验证边界

自动测试覆盖：FIPS 180-4 三组 SHA-256 向量、百万字节流式输入、真实临时文件匹配/不匹配、空缺字节验证、验证记录与版本校验和不一致、验证加入后旧复核失效、来源变更后二次关闭，以及任意非空文字、非法十六进制、纯电子转录、缺页码和缺原文。另以旧数据库复现历史门禁并确认迁移后撤销资格。测试中的合成字节与校验和只验证状态转换，不代表真实古籍。
