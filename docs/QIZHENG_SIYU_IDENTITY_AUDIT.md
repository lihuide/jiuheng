# 七政四余十一曜身份目录审计

## 本版完成范围

v0.48.0 首次在跨平台核心中建立不含解释的七政四余身份目录：

- 七政：日、月、岁星、荧惑、填星、太白、辰星；
- 四余：紫气、月孛、罗睺、计都；
- 四余传世五行名义：木余、水余、火余、土余；
- 紫炁、罗㬋、罗喉等异名显式保存，不在输入层悄悄改写原文。

目录只回答“收到的传统名称有哪些”。它不回答四余等同哪个现代天文点，也不计算十一曜位置、入宿度、十二宫、命盘、限法或吉凶。

## 证据边界

本轮公共电子文本可稳定支持七政、四余的合称与四余五行名义；相关明清材料同时显示四余来源、定义和历算角色存在历史争论。当前取得的是电子转录页面，不是已经绑定版本、页码和字节哈希的影印底本，所以只能支持身份研究目录，不能生成正式 Rule ID。

机器档案位于 `data/research/qizheng-siyu-identity-candidates.json`。档案逐项记录来源能力与限制，并把下列状态固定为 `false`：

- 四余现代天文角色已选择；
- 行星位置算法已选择；
- 宿度边界模型已选择；
- 十二宫制已选择；
- 位置已计算；
- 命盘已生成；
- 解释、信号或规则可以运行。

## 禁止推定

在原典、历算定义和误差模型闭合前：

- 不把罗睺、计都自动绑定为现代升交点和降交点；
- 不把月孛自动绑定为月球远地点；
- 不为紫气虚构现代天文点；
- 不从 `kinastro`、Horosa 或其他参考实现复制位置定义、宫制、限法和断语；
- 不从十一曜身份目录生成中间信号、应期、行动建议或最终结论。

## 快照与界面

有完整出生参数时，`BirthTimeAuditSnapshot v7` 保存这份身份目录及失败关闭状态；顶层天文快照升级为 v23。开发者模式可以看到七政、四余、异名所属目录以及未开放项。

旧 `BirthTimeAuditSnapshot v1–v6` 和天文快照 v1–v22 继续按原结构读取。旧记录缺少十一曜目录时明确显示“旧记录未保存”，不会在读取时补造数据或改变原有哈希。

## 下一阶段门禁

后续只有依次完成下列工作，才能继续生成机械星位候选：

1. 为四余各历史系统建立版本化定义和异文表；
2. 选定七政与四余的离线位置算法，并给出覆盖公元前 1000 年至公元 3000 年的误差预算；
3. 固定宿度边界、历元、岁差和宫制，不混用互不相容的体系；
4. 以独立天文来源做边界对拍；
5. 再对命盘、限法和断法逐条建立影印证据、条件、反例与 Rule ID。
