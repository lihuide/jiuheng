# 逐规则完整证据档案审计（v0.69.0）

## 目的

v0.68.0 已能指出一条规则缺少哪些门禁步骤，但研究人员仍需分别查询规则、版本、片段、影印验证、复核和测试表，才能确认现有证据具体是什么。v0.69.0 增加只读证据档案，把同一 Rule ID 的全链数据集中展示，并重新计算关键哈希以发现陈旧状态或异常修改。

## 档案内容

- 规则：术式、适用古代问题类型、证据等级、稳定性、时代、书名、卷篇、原文、版本、来源定位、异文、实现版本、确定性条件/结果/应期程序和行动字段。
- 来源：主原文、注本、异文或反证关系；版本类型、馆藏机构、目录号、影印定位、规范 SHA-256；卷页原文、规范文本、异文和转录状态。
- 实际字节验证：软件读取的文件名、字节数、匹配 SHA-256、验证器版本和验证时间。不保存原文件路径或文件内容。
- 复核：书目、转录、逻辑、实现四类记录，以及复核人、结论、说明、时间和所绑定的规则/证据哈希。历史失效记录保留并标记，不冒充当前复核。
- 测试：全部启用/停用用例、输入、完整预期输出、边界分类、出处依据；测试运行的实现版本、通过/失败数、环境、时间和绑定哈希。

## 三类独立重算

档案不会只相信数据库中的现成状态，而是以当前记录重新计算：

1. 规则正文规范哈希；
2. 关联版本、片段、来源关系及影印验证组成的文献证据包哈希；
3. 当前启用测试用例组成的测试套件哈希。

界面同时显示存储值与重算值。任一不一致只会显示红色异常并由既有门禁失败关闭，不会自动修复、覆盖或批准。

## 安全边界

- 档案 API 只执行查询和纯哈希计算，不刷新证据状态，不写 SQLite。
- 开发者界面没有规则编辑、复核批准、测试结果填写或发布按钮。
- 是否可执行仍只由 `rule_release_readiness` 视图、`rule_hits` 触发器及运行时重新编译/重放共同决定。
- 档案中的数量、完整度和哈希一致性不形成术式权重、现实概率或古籍依据等级。
- 正式规则包为空时仍显示 0 条，不创建示例规则或占位断法。

## 自动验证

- 不存在的 Rule ID 返回空档案，而不是伪造记录。
- 完整测试夹具能重建一条主来源、影印验证、四类复核、测试用例、运行环境与当前门禁。
- 三类存储哈希与独立重算值逐项一致。
- 人工篡改测试套件状态后，档案明确报告不一致，测试门禁与最终可执行状态同时关闭。
