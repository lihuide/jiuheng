# 不二占事件指纹与规则匹配审计

## 边界

本模块只判断“当前输入是否与已经锁定的事件相同”，不用 AI、向量模型、网络服务或不可解释的概率模型。它不判断占问是否合理，也不输出术数结论。

当前算法版本：`jiuheng.event_match.rule_similarity.v3`。

## 两级识别

第一层是规范化事件指纹。下列字段经过小写化、空白/标点清理和有限的时间写法归一后，以 BLAKE3 生成确定性摘要：

- 固定问题类别与映射后的古代问题类型；
- 主体、客体、目标事件；
- 国家、省、市、区县、街道；
- 目标时间范围；
- 关键词、同义词映射结果；
- 多选项集合（顺序不影响集合）。
- 长期命理记录提供的性别、出生北京时间与出生行政地点。

摘要完全一致时直接拦截。指纹 v2 不包含占问点击时刻、记录 UUID 或随机材料，因为这些字段变化不代表现实事件发生变化。

第二层用于识别合理改写。程序按同一古代问题类型从全部历史记录中由新到旧检查，重新从不可变的历史参数和当时保存的关键词构造当前比较表示。旧版 v1/v2 摘要不会被覆盖或改写。

## 防误拦截硬门槛

以下任一明确冲突都会判为不同事件，不进入相似度阈值：

- 古代问题类型不同；
- 两个固定类别不同（“其他”映射到同一古代类型是明确例外）；
- 国家、省或城市不同；
- 两边都提供区县/街道且值不同；
- 两边都提供主体或客体且值不同；
- 两边都提供目标时间范围且规范值不同；
- 两边都是多选题但候选集合不同。
- 出生参数不同，或只有一边提供了出生参数。

这意味着“同一地点明天是否下雨”和“同一地点七天后是否下雨”不会仅因文字接近而被阻止。

## 可解释相似分数

通过硬门槛后，分数只由固定权重规则产生：类别、行政地点、主体、客体、目标事件中文字二元组的 Sørensen–Dice 相似度、关键词集合相似度、目标时间和候选集合。达到 75 分仍不够；目标事件还必须达到最低文字结构相似度，或同时具有较强关键词重合、明确主体/客体锚点和最低事件文字重合。

界面显示：

- 完全指纹匹配或多字段规则匹配；
- 0–100 的规则分数；
- 每项命中依据；
- 开发者模式下的算法版本。

分数只表示事件身份规则的相似程度，不是现实概率、占断可信度或古籍证据等级。

## EVENT_REVISION

命中同一事件时默认阻止再次锁定。只有用户填写现实情况的实质变化，才会建立 `EVENT_REVISION`。新记录保存前一记录 UUID、变化说明、建立时间，以及触发拦截的算法版本、是否完全摘要命中、分数和理由。历史页可沿前后链查看。

旧版修订记录没有这些新增审计字段时继续可读，并明确显示“旧记录未保存”，绝不补造历史分数。

## 数据完整性

SQLite 迁移 v6 扩展了修订审计字段，并强化锁定记录触发器：指纹版本、摘要和规范关键词与问题原文、参数、地点、时间一起不可修改。指纹 v3 新增出生身份字段；算法升级只影响新比较，不静默重写旧摘要。

v0.64.0 又在新占问写入入口核对调用方提交的分类和指纹：先从锁定类别、原文重新运行纯规则分类器，再从完整问题重建指纹；任一不一致即拒绝写入。此项不改变 v3 指纹格式，不重算或改写旧占问。详见 [“其他”分类安全审计](OTHER_CLASSIFICATION_SAFETY_AUDIT.md)。

## 已知限制

- 时间归一只覆盖明确登记的有限同义写法，不试图理解任意自然语言日期。
- 中文事件相似度使用确定性的字符二元组，不具有语义模型的推断能力。
- 主体、客体或时间信息留空会减少可用识别证据；系统宁可不拦截边界不清的改写，也不以低证据强行认定同一事件。
- 若不同现实事件恰好使用相同主体、客体、地点、时间和高度相似的目标描述，仍可能需要用户通过具体字段把它们区分开。
