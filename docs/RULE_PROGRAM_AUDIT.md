# 确定性规则程序审计

## 目的

古籍原文和整理说明可以是自然语言，但程序不能把自由文本直接当作可执行断法。0.32.0 将 `RuleRecord` 的 `condition_expression`、`result_expression` 和可选 `timing_expression` 固定为三个版本化 JSON 程序；只有结构、证据、复核和真实测试运行全部通过的规则才能进入运行时。

本层不是 AI、脚本解释器或通用表达式求值器。它不联网、不读取外部状态，也不把原文自动翻译为规则。

## v1 输入与条件

条件程序顶层必须是：

```json
{
  "schema_version": 1,
  "condition": {
    "op": "all",
    "terms": [
      { "op": "eq", "path": "/chart/enabled", "value": true },
      { "op": "gte", "path": "/chart/score", "value": 7 }
    ]
  }
}
```

条件只能通过 JSON Pointer 读取传入的不可变快照。v1 支持 `all`、`any`、`not`、`exists`、`eq`、`not_eq`、`in`、`gt`、`gte`、`lt` 和 `lte`。字面量只允许布尔值、64 位整数和字符串；不允许浮点数、`null`、对象或数组作为比较值。

失败关闭规则如下：

- 路径不存在时条件为假，不生成任何输出。
- 已存在字段与规则要求的类型不一致时，整个求值报错，不将错误值当作“不匹配”。
- 拒绝未知字段、空 `all/any`、非法 JSON Pointer、重复或混合类型的 `in` 候选。
- 单个程序最大 32 KiB；条件最多 128 个节点、16 层嵌套。
- 求值轨迹只记录操作、路径和布尔结果，不把实际输入值复制到轨迹中。

## v1 结果、应期与建议

结果程序只允许输出 12 个标准化中间信号，每项是 `-100..=100` 的整数，并且至少存在一项：

```json
{
  "schema_version": 1,
  "signals": {
    "trend": 60,
    "support": 40,
    "obstacle": -20
  }
}
```

v1 不允许规则自行写任意 `extra` 字段，也不允许输出多选项分数。应期程序只能选择核心已经定义的固定 `TimingWindow`：

```json
{ "schema_version": 1, "window": "within_one_month" }
```

行动建议仍来自 `RuleRecord` 的稳定行动键、`do/avoid` 方向和显示文本，三字段必须全有或全无，并随规则正文一起参与哈希和复核。

不匹配的规则必须产生固定审计输出：`matched=false`，且信号、应期、行动建议全部为空。匹配规则必须包含信号；预期输出中的未知字段、越界值或不一致结构都会被拒绝。

## 存储和发布门禁

SQLite 迁移 v9 撤销既有本地规则的审核状态，因为旧自由文本字段不能继承 v1 JSON 程序的实现审核。数据库视图先做 JSON、版本、长度和基本形状检查；Rust 编译器在写入规则及读取已发布规则时再执行完整语义校验。

规则测试不再接受外部代码直接申报“通过数量”。公开入口会逐条执行数据库中的启用用例，将实际输出与完整的版本化预期输出精确比较，然后由存储层记录真实的通过/失败数。种子包中的测试运行声明也会在导入时重新执行；声明计数与真实结果不同则整个事务回滚。

因此发布与运行链为：

`版本化 JSON 程序可编译 → 主影印来源完整 → 四类复核绑定当前哈希 → 启用用例自动执行且全通过 → released_rules 再编译 → 版本化运行输入 → 无冲突术内合并 → 融合前强制重放`

任一步不满足，规则都不会参与命中、融合、应期或行动建议。

## 当前边界

- 正式规则种子包仍为 0 条，规则程序基础设施的完成不表示九术古籍断法已经完成。
- v1 不支持算术、循环、函数、时间访问、随机数、文件、网络或脚本扩展。
- 古籍文字到 JSON 程序的整理仍必须人工完成，并经过书目、转录、逻辑、实现四类独立复核。
- 多选项信号的安全表示尚未纳入 v1；在完成专门结构和测试前不会用任意字段绕过。

0.33.0 新增的运行输入、术内合并和融合重放边界详见 `RULE_RUNTIME_INTEGRITY_AUDIT.md`。
