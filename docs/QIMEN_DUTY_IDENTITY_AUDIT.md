# 奇门九星八门与本旬值符值使身份机械候选审计

## 本版完成范围

0.30.0 在时旬首与地盘落宫候选之上新增：

`jiuheng.qimen.early_song_fixed_star_gate_duty_identity.v1`

程序保存：

- 一至九宫对应的九星固定身份；
- 八个有方位宫对应的八门固定身份；
- 旬首地盘落宫所对应的本旬值符星；
- 同一宫所对应的本旬值使门；
- 旬首落中五时，依本版早期宋代候选寄坤二取门；
- 时间口径、边界安全、算法版本及所有禁止解释标志。

这一层的“值符”“值使”只是本旬身份。程序尚未把值符加到时干宫，也未把值使加到时支所数宫，因此没有生成当前时刻的值符落宫、值使落宫、天盘或门盘。

## 早期来源与采用顺序

北宋《武经总要》遁甲篇完整列出九星、八门本宫，并明确中五寄坤二。其固定表为：

```text
九星：坎一天蓬、坤二天芮、震三天冲、巽四天辅、中五天禽、
      乾六天心、兑七天柱、艮八天任、离九天英。

八门：坎一休、坤二死、震三伤、巽四杜、乾六开、
      兑七惊、艮八生、离九景；中五没有独立门。
```

同篇算例直接以旬首本宫的星、门作为值符和值事。北宋《景祐遁甲符应经》公共转录独立支持九星本宫表。较晚《奇门遁甲统宗》卷二又明确写出地盘旬首所临宫之星为值符、门为值使，并给出阳一局六旬完整序列。

本项目的古籍优先原则要求在后世异说出现时优先较早、来源更强且公式完整的材料。因此中五采用明确命名的：

`early_song_center_five_hosts_kun_two.v1`

这只是本软件当前机械候选的来源说明，不宣称后世所有流派都采用同一寄宫法。已发现的阴阳遁分别寄坤、寄艮等晚期异说被记录为未决差异，不混入本候选。

详细来源与限制保存在：

`data/research/qimen-duty-identity-candidates.json`

## 身份派生算法

输入必须先通过前几层：

```text
节气与三元局数
  → 三奇六仪地盘
  → 时干支与旬首
  → 旬首所隐六仪的地盘宫
  → 本宫固定星 = 本旬值符
  → 本宫固定门 = 本旬值使
```

旬首落中五时仍以中五固定星天禽为值符，但中五没有独立门，因此先按本版早期宋代候选寄坤二，再取坤二死门为值使。对象会同时保存原旬首宫、中五寄宫是否发生、寄宫来源口径和实际取门宫，避免只留下“死门”而丢失推导过程。

阳一局的六旬锚点为：

```text
甲子：天蓬 / 休门
甲戌：天芮 / 死门
甲申：天冲 / 伤门
甲午：天辅 / 杜门
甲辰：天禽 / 死门（中五寄坤二取门）
甲寅：天心 / 开门
```

自动测试还遍历阴阳二遁各九局、每局六个旬首，要求每次值符与旬首本宫固定星一致，值使与取门宫固定门一致。

## 时间口径和失败关闭

北京时间与真太阳时各自使用自己的日干、时支、时干支、旬首和地盘，禁止跨候选拼接。本旬符使身份的机械安全继承节气、日界、时辰边界、局数、地盘和旬首落宫安全状态。

处暑仍因局数异文没有地盘，因此只能保存时干支、旬首和所隐六仪；不能生成旬首落宫，也不能生成值符值使身份。程序不会用固定星门表反向猜测一个宫位。

## 0.32.0 逐时移动复核结果

后续检索已在《景祐遁甲符应经》和《奇门遁甲统宗》的公共转录中定位到“值符随时干、值使随时支”及阳顺阴逆的公式候选，并找到阳一局、阴九局的逐时算例。不过，本轮未能取得并校验对应影印文件，因而没有准确册页、图版、逐字校勘或文件哈希；中五逐时处理、时制、日界和历法传承也未闭合。

候选与失败原因已独立记录在 `data/research/qimen-hourly-duty-movement-candidates.json`。该档案将 `implementation_allowed` 与 `runtime_rule_seed_allowed` 同时固定为 `false`，自动门禁要求它不能进入排盘或规则种子。因此 0.32.0 没有新增逐时移动算法。

## 明确没有实现

截至 0.32.0 仍没有实现：

- 值符加时干后的当前时刻落宫；
- 值使从旬首宫数到时支后的当前时刻落宫；
- 中五在逐时飞转阶段的额外处理；
- 天盘三奇六仪、九星飞布、门盘、八神；
- 星门旺衰、门迫、击刑、格局、用神、吉凶、应期；
- 中间信号、Rule ID 或综合裁决。

`duty_chief_hourly_palace` 与 `duty_envoy_hourly_palace` 恒为空，`heaven_plate_calculated`、`interpretation_eligible` 和 `rule_eligible` 恒为 `false`。

## 快照与兼容

顶层天文审计快照从 v20 升级到 v21，奇门审计对象从 v3 升级到 v4，时旬首对象从 v1 升级到 v2。新字段 `duty_identity_candidate` 可空。

v20 历史记录没有符使身份，读取时保持为空；开发者重算只比较 v20 已存在的局数、地盘和时旬首字段。v19 继续只比较局数与地盘，v18 只比较局数。任何旧记录都不会补造新字段、重写 JSON 或改变哈希。
