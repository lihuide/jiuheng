# 民用历法同瞬间换算审计

## 输入口径

桌面端统一接受 `YYYY-MM-DD HH:MM:SS` 的前推格里高利历（proleptic Gregorian）北京时间输入，不让同一个输入框随年代静默切换历法。公元前采用天文学年编号：

- `0000` = 公元前 1 年；
- `-0001` = 公元前 2 年；
- `-0999` = 公元前 1000 年。

当前产品输入范围固定为天文年 `-999..=3000`。该范围同时受桌面层与核心参数校验器约束；绕过界面写入也会被拒绝。

## 三种同瞬间表示

`jiuheng.civil_calendar_views.v1` 先把输入换算为儒略日，再从同一个儒略日反算：

1. 前推格里高利历；
2. 前推儒略历；
3. 1582 改革历：1582-10-04 及以前按儒略历，下一日为 1582-10-15 格里高利历。

改革历若被直接用来解释 `1582-10-05` 至 `1582-10-14` 会返回明确的“日期不存在”错误；由一个真实儒略日反算改革历时则不会制造缺失日期。三种表示保留相同的时、分、秒，并通过反向儒略日一致性测试。

## 持久化与复现

- 占问天文快照升级为 v8，增加上述三种历法表示、输入历法、儒略日和算法版本。
- 出生时间机械审计升级为 v2，独立保存出生时刻的同一组历法表示。
- 开发者模式和永久记录页显示固化值，并与当前算法逐字段重算。
- 天文快照 v1–v7 和出生审计 v1 缺少新字段时仍可读取，不补写、不静默升级、不改算历史值。

## 明确边界

这只是民用历法数学换算，不是中国传统农历、朔望月、置闰或任何术式的年/月边界规则。它不参与推演裁决，也不能替代尚未完成的全范围高精度天文、传统历法和古籍口径验证。
