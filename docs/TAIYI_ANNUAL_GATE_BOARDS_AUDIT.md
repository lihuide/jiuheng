# 太乙岁计开门锚定八门子盘机械候选审计

本页记录 v0.43.0 新增的岁计八门机械候选。它只处理卷一“推八门占岁计法”明确列出的三个已有锚点：太乙、主大将、客大将。每个锚点各自把开门置于所在宫，再按同一八方环序排完其余七门。它不处理時計直门，不判断开休生会合、门具将发、八门杜、胜负或吉凶。

## 岁计与時計严格分域

卷一相邻两段采用不同锚点：

- “推八门用法”属于時計，要求以当时直门加太乙及主客大将，并说明按时移动；
- “推八门占岁计法”属于岁计，明确分别以开门加太乙、主大将、客大将和定计大将。

v0.43.0 只实现第二段中已经拥有独立宫位字段的前三项。岁计直门的三十年周期仍作为另一个字段保存，但不会被错误拿来替换岁计子盘的开门锚点。時計直门的起法、移动和日期换算继续关闭。

## 八方旋转

八门与太乙宫数的固定环序是：

```text
门：开、休、生、伤、杜、景、死、惊
宫：一、八、三、四、九、二、七、六
方：乾、坎、艮、震、巽、离、坤、兑
```

对每个非中宫锚点执行同一机械步骤：

```text
1. 在八方环中找到锚点宫；
2. 把开门放在锚点；
3. 门序与宫序同时逐位左行；
4. 八门各占一个外宫，不重复、不遗漏。
```

例如太乙一宫时得到固定目录；主大将在七宫时，门宫依次为开七、休六、生一、伤八、杜三、景四、死九、惊二。这里只表达相对位置，不表达门的好坏。

## 中五宫失败关闭

主客大将由主客算约减，可落中五宫；但传本八门只列乾、坎、艮、震、巽、离、坤、兑八方，没有中五宫门位。若把五宫强制寄往坤二、艮八或任一外宫，会引入未取得原文依据的规则。

因此：

- 太乙自身不游中五，太乙子盘始终可以生成；
- 主大将在五宫时，主大将子盘为 `None` 并保存明确原因；
- 客大将在五宫时，客大将子盘同样失败关闭；
- 另一个非中宫大将的子盘不受牵连；
- `all_three_boards_generated` 只在三个子盘均存在时为真。

第一阳局的太乙一宫、主大将七宫、客大将三宫成为三套完整锚点。第四局主大将五宫和第七局客大将五宫成为中五失败关闭锚点。

## 仍未实现

- 卷一同段列出的定计大将及其第四套八门；
- 時計直门求法及太乙三时、大将一时的移动；
- 中五宫是否存在特定传承的寄宫规则；
- 开休生三门会合、闭塞、门具将发、八门杜和三门五将；
- 击、迫、关、对与其他复合格局；
- 现代日期到积年或局序、自动选遁；
- 所有解释、标准信号、应期、行动建议和正式 Rule ID。

## 自动验证

- 八个非中宫锚点逐一旋转，八门和八宫都必须恰好出现一次；
- 一宫、七宫、三宫三套完整门盘与机器档案逐格一致；
- 第一、第四、第七积年分别覆盖三盘完整、主大将中五、客大将中五；
- 1–720 积年全部核对“子盘存在”等价于“大将不在五宫”；
- v1–v5 年计 JSON 缺少新字段时读为 `None`，绝不静默补算历史记录；
- 每个子盘和总候选都固定禁止解释、信号和 Rule ID。

完整机器档案见 `data/research/taiyi-annual-gate-boards-candidates.json`。本层提高的是可复现排盘机械能力，不提高任何传统断法证据等级，也不让太乙进入综合裁决。
