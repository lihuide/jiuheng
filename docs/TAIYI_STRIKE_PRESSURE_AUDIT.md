# 太乙“击、迫”方向位置标记机械候选审计

本页记录 v0.45.0 在 v0.44.0 无方向邻位几何之上新增的“击、迫”位置标签。卷三正文给出前后、内外名称，五将立成表又为程序十六位环的正负方向提供独立锚点，因此可以在不采用任何吉凶解释的前提下完成机械分类。“关”和后续复合格局仍未实现。

## 方向怎样闭合

v0.44.0 已保存四种固定环序几何，但当时没有把 `+/-` 直接等同古籍的前后、内外。卷三五将立成表提供了独立标记：

| 天目与太乙 | 环序位移 | 立成表标记 | 固定方向 |
|---|---:|---|---|
| 武德与太乙六宫 | `-1` 辰 | 天目内迫 | `-1` 为后/内 |
| 武德与太乙七宫 | `+1` 辰 | 天目外迫 | `+1` 为前/外 |
| 和德与太乙四宫 | `-2` 宫 | 天目内迫 | `-2` 为后/内 |
| 和德与太乙八宫 | `+2` 宫 | 天目外迫 | `+2` 为前/外 |

另有“阳德、太乙二宫”格：按既有主算公式得到主算十七、主大将七宫；七宫相对太乙二宫为 `+2`，立成表同时记“大将外迫”，闭合了四将方向。

因此程序固定：

```text
+1 辰 = 前 / 外辰
-1 辰 = 后 / 内辰
+2 宫 = 前 / 外宫
-2 宫 = 后 / 内宫
```

这项映射由传本表格验证，不是代码数组自行命名。

## 始击的“击”

卷三“推击法”只以客目，即当前机械对象始击，为主体：

| 几何 | 程序值 | 显示名 |
|---|---|---|
| `+1` 辰 | `front_chen` | 前击 |
| `-1` 辰 | `rear_chen` | 后击 |
| `+2` 宫 | `outer_palace` | 外宫击 |
| `-2` 宫 | `inner_palace` | 内宫击 |

不在这四个邻位时 `shiji_strike = None`。`strike_classified = true` 表示当前版本已执行完整位置检查，不表示一定命中“击”，更不表示吉凶。

## 文昌及四将的“迫”

卷三先列上下二目和主客大小四将，又明确说“上目无迫”；“推对法”进一步明称“下目文昌”。因此程序：

- 只为文昌机械对象天目生成辰迫或宫迫；
- 不为始击生成迫；
- 为主大将、主参将、客大将、客参将检查相邻正宫；
- 四将没有辰位，故只可能生成外宫迫或内宫迫；
- 中五宫不在十六位外环，不生成迫，也不猜测寄宫。

压力枚举为 `outer_chen`、`inner_chen`、`outer_palace`、`inner_palace`。`pressure_classified = true` 同样只表示检查完成。

## “关”仍不实现

卷三“客主大小将目相宫齐为关”“主客大小将同宫数齐皆为关日”不能唯一确定每个“将—目—主客”的配对。立成表又出现“大将关囚”“大小将关”“天目大将关”等复合简写，不能在未拆清主体和宫数前还原为一条通用布尔公式。

因此继续固定：

```text
barrier_classified = false
```

四郭固、四郭杜、执提、提挟及三门五将胜败结论也全部关闭。

## 解释层继续隔离

正文关于君臣、灾缓急、先起后起、胜败等内容未进入代码。击迫字段不会：

- 生成任何 `-100..=100` 中间信号；
- 生成结论、概率或应期；
- 生成行动建议；
- 生成正式 Rule ID；
- 让太乙参与综合裁决。

- 第 2、4、10、12、14、15 算覆盖主客四将内外宫迫；
- 1–720 算逐项重新由盘面计算全部击迫字段；

- v7/v2 和 v6/v1 历史 JSON 均验证不会静默升级；
- 研究档案及机械字段均被阻止进入空的正式规则种子包。
