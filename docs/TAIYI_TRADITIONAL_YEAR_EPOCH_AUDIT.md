# 太乙传统年标签—积年桥接审计

更新日期：2026-09-27。源码研究增量，桌面发布版本仍为 v0.75.0。

## 实际新增的核心能力

Rust 核心现在可从**明确给定的传统年标签**，按一套显式请求的传本历元候选，推得积年并接入既有年计机械盘。此前只能要求调用方直接给出积年数。

这不是现代日期自动起局：传统年标签的岁首可能涉及冬至、正月或其他传承，尚未取得已复核依据，函数不接收日期/时刻，不把电脑日期的“年”默认为术式年，也不自动采用正月初一或立春。

## 来源与排除项

固定 Kanripo 提交 `e3264da2c9f556225e056abe7eade01903b4543e` 的《太乙金镜式经》卷一，页标 `001-3a/3b`：开元十二年甲子积得 **1,937,281 算**，上考每年减一、下检每年加一。本轮重新下载该电子文件 22,044 字节，SHA-256 与既有档案闭合为 `6b13ff06e980439d7a3611f1f10c9efb318513e23f7a9e4c16ed4e8896f162d4`。[原转录](https://github.com/kanripo/KR3g0047/blob/e3264da2c9f556225e056abe7eade01903b4543e/KR3g0047_001.txt)，[台湾大学年表交叉核对](https://dlbs.liberal.ntu.edu.tw/museum/silk/db/index-year-table4.html)支持开元十二年对应 724、甲子。

候选公式为 `积年 = 1,937,281 + (传统年标签 − 724)`。例如标签 2026 得 1,938,583 算，太岁身份闭合丙午；这不等于声明某个 2026 日期已经进入该术式的传统年。

同一传本另写“开元十五年甲子”与 40,801 算；十五年对应 727、丁卯，与甲子矛盾。程序没有提供这一历元选项，不能擅自改字使它闭合。开源项目常见千万量级积年常量也未导入。本候选没有默认值，须显式传入 `ReceivedKaiyuan12Year724Count1937281`；显式研究请求不等于正式运行批准。

## 已验证的算法边界

- 输入采用天文年编号：0=公元前1年，−999=公元前1000年；支持标签 −999 至 3000。
- 穷举全部 4,000 个标签，太岁干支均与独立的年标签六十循环闭合，积年逐年严格增一。
- 年计盘完整复用既有给定积年 API，旧算法版本与历史快照不变。
- 边界、极值、公元前跨零、锚年前后、序列化确定性和非法历元选项均有测试。
- 影印核验、年界选择、正式历元、完整局式、信号、应期、行动建议与 Rule ID 标志保持关闭。
