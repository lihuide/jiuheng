# 中间信号与同权综合裁决审计

## 安全入口

融合算法版本为 `jiuheng.signal_fusion.equal_method_weight.v2`，信号结构版本为 v1，行动建议结构版本为 v1。纯 Rust 算法不访问网络、不使用 AI，也不自行解释古籍。

产品运行时只能从 SQLite 读取满足以下条件的术式结果：

1. `engine_runs` 已完成且适用性为 `applicable`；
2. 至少命中一个非空 Rule ID；
3. 该术式的每个命中 Rule ID 在融合当下仍通过字段、主版本原文、四类复核和当前测试套件门禁；
4. Rule ID 的术式、适用古代问题类型和证据等级与引擎结果一致；
5. 中间分数全部位于 `-100..=100`。

古法行动建议还必须逐条绑定上述命中 Rule ID，使用有效的稳定行动键，并具有已经审核的“建议/避免”方向、显示文本和非未核验证据等级。详细失败关闭策略见 `ACTION_ADVICE_AUDIT.md`。

任一条件不满足，该术式不进入融合。没有合格术式时返回明确错误，问题继续保持 `not_executable`，不产生结论。自动测试中的 MethodResult 夹具只存在于测试进程，不会写入正式规则种子包。

## 统一信号

`IntermediateSignals v1` 保存趋势、主客强弱、阻力、助力、结果方向、变化速度、主动/被动、得失、吉凶、稳定度、外部干扰、时间区间和多选项分数。

其中只有具备明确正负语义的字段进入方法结果分：

- 趋势；
- 主体强弱减客体强弱；
- 阻力取反；
- 助力；
- 结果方向；
- 得失；
- 吉凶；
- 外部干扰取反。

变化速度、主动/被动和稳定度保留在逐维度审计中，但不被擅自解释为吉或凶。每个术式先对自身可用的方向字段取平均，只生成一个方法分；随后 N 个术式各以 `1/N` 进入总分。因此字段较多的术式不会变相获得更大权重，问题类型也不会改变术式权重。

## 冲突与古籍等级

方法分绝对值达到 15 才视为明确方向。正反方法同时存在但同权总分仍有明确方向时，直接使用同权总分，不调用古籍等级。

只有正反方向同时存在且同权总分落入 `-14..=14` 的僵局，才从明确方向的方法中选取最高古籍证据等级破局。若该等级内部仍完全相抵，算法返回 `UnresolvedConflict`，不按术式名称、输入次序或人为优先表强行选边。

最终展示的证据等级取全部参与术式中的最低等级，采用保守口径；这与僵局时寻找最高等级破局是两个不同字段，完整记录在 `ConflictBreakAudit` 中。

## 时间与多选项

时间只融合非“暂无法断定”的标准区间。算法取排序后的中位区间；偶数个输入取较晚的一个，以避免输出比任何中间共识更激进的精确时间。全部缺少时间信号时输出“暂无法断定”。

多选项比较要求每个参与术式为全部锁定选项提供一一对应的分数，不允许漏项、增项或改名。每个选项按术式同权求分，唯一最高项直接胜出；只有最高项完全并列时才启用同一套古籍等级破局。最高等级仍并列则失败关闭。

## 固化与复现

SQLite 迁移 v7 新增 `fusion_decisions`，迁移 v8 增加行动建议字段与摘要交叉校验：

- 保存算法版本、信号版本、完整 FusionDecision JSON、BLAKE3 内容哈希与创建时间；
- 数据库触发器禁止更新和删除；
- 同一占问再次请求融合时读取原快照，不覆盖历史裁决；
- 历史页开发者模式显示每术 `1/N`、方法分、Rule ID、证据等级、行动建议来源/冲突隐藏项、冲突破局和完整轨迹；
- 哈希或版本索引不一致时拒绝读取。

当前正式规则种子包仍为 0 条，所以本版完成的是可执行且失败关闭的综合裁决及建议基础设施，不代表任何九术断法已经放行，也不会让现有占问生成占位结论或古法行动建议。
