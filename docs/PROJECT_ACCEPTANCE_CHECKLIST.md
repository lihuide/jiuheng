# 项目逐项验收清单（v0.77.0）

## 严格验收计数与历史工程粗估

此前反复沿用的“约 69%”是工程开发的历史主观粗估，缺少稳定的分母、权重和逐项验收记录，自 v0.66.0 起不作为正式验收指标。2026-10-02 又按“九术具备已核古籍规则并能正式裁决的完整成品”另估约 25%，却误写成可与旧工程数字比较的总体进度，现撤回。两种数字不能相减，项目没有倒退。当前以逐项验收状态和正式规则、完整可裁决术式数量报告可核进展；需要新的百分比时，先固定计算口径。

一级需求彼此工作量差异很大，因此下面的数量**不能换算成百分比**。只有一项的全部验收条件均满足，才标记“已通过”；已有部分实现但未闭环标记“进行中”；关键前置证据缺失且当前无法闭环标记“未通过/受阻”。机器可读清单是 `data/progress.checklist.json`，桌面软件“范围与声明”页直接读取并展示同一份数据；程序版本与清单版本不一致时显示错误，而不是沿用旧状态。

硬指标仍是：正式 Rule ID 为 0，能够完成正式裁决的术式为 0/9。这不否认已经完成的工程层，也不把工程层冒充成可用占断能力。

## 验收规则

1. 清单必须按 `REQ-01` 至 `REQ-16` 完整覆盖原始一级需求，不得跳号或重排。
2. 每项必须同时保存已有证据和剩余验收条件，不能只写状态。
3. 清单内禁止百分比字段；自动测试拒绝旧的 69、87 等粗估数字重新进入机器清单。
4. 版本发布时清单的 `product_version` 必须与程序版本一致。
5. 功能新增不自动改变状态；只有相应剩余验收条件真正闭合后才能更新。
6. 正式规则数量、九术裁决数量等可验证计数单独报告，不与非等权一级需求相加。

完整逐项文字以 `data/progress.checklist.json` 为唯一当前状态源；历史文档里的旧粗估只代表当时曾使用的口径，v0.66.0 后不再有效。
