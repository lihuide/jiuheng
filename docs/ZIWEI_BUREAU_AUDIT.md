# 紫微斗数宫干、纳音与五行局机械审计

## 本版范围

0.25.0 在既有命宫、身宫和十二宫地支候选之上，增加以下无解释结构：

- 以出生年干确定寅宫天干；
- 从寅宫顺排十二地支宫干；
- 以命宫干支查询六十甲子纳音；
- 把纳音五行映射为水二局、木三局、金四局、土五局或火六局。

宫干与五行局算法版本为 `jiuheng.ziwei.received_yin_stem_nayin_five_element_bureau.v1`；共享纳音目录版本为 `jiuheng.nayin.received_sixty_designations.v1`。这些结果只供机械排盘、历史重算和开发者核验，不安紫微星或其他星曜，不产生 Rule ID、吉凶、应期、中间信号或综合裁决。

## 传本公式

《紫微斗数全书》卷二的电子转录列出“起五行寅例”：

| 出生年干 | 寅宫起干支 |
|---|---|
| 甲、己 | 丙寅 |
| 乙、庚 | 戊寅 |
| 丙、辛 | 庚寅 |
| 丁、壬 | 壬寅 |
| 戊、癸 | 甲寅 |

同页随后列出六十花甲子三十组纳音，并用“甲生人命在寅”为例，以丙寅、丁卯的炉中火进入火局。

《新刻纂集紫微斗数捷览》卷一“定五局例”的电子转录把中间步骤说得更完整：从寅宫起遁甲纳音，顺数至命宫定局。其算例包括：甲己年命在寅或卯为炉中火、火六局；命在辰或巳为大林木、木三局；乙庚年命在子或丑为霹雳火、火六局。

晚清俞樾《游艺录》的 OCR 另有“以遁甲纳音定五局”的独立方法链线索。全部来源、馆藏线索、URL 和限制保存在 `data/research/ziwei-palace-stems-bureau-candidates.json`。

## 程序实现

寅宫天干索引按十天干取模，随后天干与地支同步顺行。每一个宫干支必须能在六十甲子中找到唯一位置；程序不会拼出阴阳奇偶不配的非法干支。

共享纳音目录按六十甲子相邻两项为一组，共三十组。目录只保存规范化中文名和五行类别。五行局的机械标签固定为：

- 水 → 水二局；
- 木 → 木三局；
- 金 → 金四局；
- 土 → 土五局；
- 火 → 火六局。

局数在本层只是传本排盘标签，不代表现实属性、概率、旺衰或吉凶。

## 两种年干 × 两种时辰

所核文字写“生年”“本生年”，但没有解决现代软件在春节前后应采用名义农历年，还是采用立春换年。程序因此并列保存：

1. 现代官方农历日期候选的名义农历年干；
2. 精确天文立春边界形成的年干候选。

命宫本身又保留北京时间与真太阳时两套时辰口径，因此最多形成四套宫干/五行局组合。`selected_year_stem_convention` 和 `selected_hour_convention` 始终为空；结果偶然一致也不等于口径争议已经解决。农历日期、立春或时辰落在不确定边界内时，对应候选的机械安全状态关闭。

## 版本与历史兼容

`ZiweiLifeBodyAudit` 从 v1 升级到 v2，`BirthTimeAuditSnapshot` 从 v5 升级到 v6，顶层天文快照从 v15 升级到 v16。旧顶层 v1–v15、出生审计 v1–v5 及紫微审计 v1 均保持原始 JSON 可读；缺少宫干/五行局字段的旧记录显示“旧记录未保存”，不会补算、改写或改变旧哈希。

## 自动验证与证据门禁

测试覆盖：

- 十个出生年干的寅宫起干及全部十二宫合法干支；
- 六十干支与三十纳音一一成对；
- 五种纳音元素各有六组；
- 《全书》《捷览》的炉中火、火六局、大林木、木三局和霹雳火算例；
- 农历年干与立春年干不同时保留平行候选；
- v15/v5/v1 历史快照缺少新增字段时仍可读取和重算匹配；
- 研究记录不能进入空的正式规则种子包。

主版本影像页、纳音异文、出生年界、时辰口径和星曜层未全部闭合前，紫微斗数继续保持“仅排盘、不裁决”。
