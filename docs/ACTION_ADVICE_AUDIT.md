# 当下行动建议审计

## 输出边界

结果页在“结论”和“时间”之后显示“当下建议”，再显示“古法依据等级”。其中分为两个来源完全不同的部分：

1. 古法行动建议：只能来自本次实际命中的、融合当下仍通过发布门禁的 Rule ID。
2. 现实行动底线：按问题类别固定显示的安全提示，用于提醒用户核实现实信息、遵守专业意见和避免高风险误用；它不参与推演、不改变结论，也不声称来自古籍。

当前正式规则种子包为 0 条，因此软件会显示“暂无可靠古籍行动建议”。这表示建议链已经实现，但还没有任何古籍行动规则完成书目、转录、逻辑、实现复核和边界测试，不能用通用话术代替。

## 规则字段与发布门禁

RuleRecord 新增三个可选字段：

- `action_key`：最长 96 字节的稳定机器键，只允许小写 ASCII 字母、数字、点、下划线和连字符，并须以字母或数字开头、结尾；
- `action_polarity`：`do`（建议）或 `avoid`（避免）；
- `action_expression`：普通界面显示的完整行动表达。

三个字段必须全有或全无。它们进入规范 RuleRecord JSON 和 BLAKE3 正文哈希，因此任何建议文字、方向或行动键变化都会使旧复核和旧测试运行失效。SQLite 迁移 v8 主动撤销按旧哈希结构审核的本地规则，避免旧审核状态被误继承。

规则仍须同时满足稳定性、证据等级、主版本原文、影印定位、书目/转录/逻辑/实现四类批准和当前边界测试套件全通过，才能写入 rule_hits 并被运行时读取。

## 汇总与冲突

每个术式提交的建议必须引用该术式自己的 `hit_rule_ids`。融合层拒绝未绑定 Rule ID、重复 Rule ID、非法行动键、空文本或未核验证据等级。

汇总按 `action_key` 进行：

- 同一方向、同一文本的重复建议合并，保留全部来源术式和 Rule ID；
- 同一方向但文本不同的建议分别保留，便于审计原规则表达；
- 同一行动键同时出现“建议”和“避免”时，整项隐藏并记录到 `suppressed_action_keys`；
- 冲突不按数量、多数票、术式名称或信号总分强行选择。

建议结果状态包括“可用”“部分可用”“存在冲突”和“暂无已核验建议”。没有可显示项时明确失败关闭，不从结论分数生成类似“谨慎行事”的占位话术。

## 存储与复现

FusionDecision 保存建议结构版本、状态、显示项、被隐藏行动键、说明和轨迹，并继续由不可变 JSON 与 BLAKE3 哈希保护。questions 表另存最终建议摘要，历史读取会比较两者；任何不一致都作为融合审计错误拒绝展示。

旧版 FusionDecision 没有建议字段时，反序列化为“暂无已核验建议”，不会回填或猜造历史建议。开发者模式可以查看每条建议的行动键、方向、文本、证据等级、来源术式、来源 Rule ID、冲突隐藏项和完整轨迹。

## 现实安全底线

现实行动底线由固定问题类别决定，不读取信号分数，也不冒充 Rule ID。健康类明确要求不用于诊断、治疗选择、停药或延误就医；官非、财务、天气、出行、失联和人身风险分别要求以有资质专业人士、官方信息和现实应急措施为准。

这层提示的目的不是替用户作决定，而是确保文化推演不会覆盖医学、法律、财务和安全领域的现实责任。
