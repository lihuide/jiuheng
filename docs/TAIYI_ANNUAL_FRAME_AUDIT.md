# 太乙年计机械框架候选审计

本页记录 v0.37.0 在 v0.36.0“外部积年→太乙所在宫”基础上新增的四项机械字段：太岁、天目、计神、合神。输入仍然只能是调用方已经给定的、一基正整数积年；程序没有“现代日期→积年”入口，也不生成完整太乙局或任何解释结果。

本页保留 v0.37.0 当时的边界。v0.38.0 已在独立审计中增加始击、主算与客算，见 `TAIYI_EYES_COUNTS_AUDIT.md`；它没有改写本档案或把新字段伪装成 v0.37.0 已有能力。

## 字段与传本公式

### 太岁

卷一 `KR3g0047_WYG_001-3b` 至 `4a` 的“推太岁所在法”要求先以三百六十、六十约减，再从甲子算外。代码保存一至六十的一基位置、完整干支和太岁地支。第 1 算为甲子，第 60 算为癸亥，第 61 算重新为甲子。

### 天目

卷一 `KR3g0047_WYG_001-4b` 的“推天目所在法”规定十八算一周，从武德顺行十六神，在阴德、大武各重留一算。卷二 `5b` 至 `7a` 给出十六神身份目录；卷三 `9b` 至 `14a` 的阳局立成表给出 72 局逐行结果。

规范化后的十八算序列是：

```text
武德、太蔟、阴主、阴德、阴德、大义、
地主、阳德、和德、吕申、高丛、太阳、
太炅、太神、大威、天道、大武、大武
```

只有第二个阴德和第二个大武位置标记为“重留”。程序不把重复神名误判为两个不同神。

### 计神

卷一 `KR3g0047_WYG_001-4b` 规定从寅逆行十二辰。卷三立成表的前 24 局明确重复：

```text
寅、丑、子、亥、戌、酉、申、未、午、巳、辰、卯
```

代码同时测试首轮十二算和一至七百二十算的周期不变量。

### 合神

卷一 `4b` 至 `5a` 规定太岁在子时合神在丑，随后逆行十二辰、十二年一周；同卷“推六纪月建法”再次给出首位“合神丑”。规范序列为：

```text
丑、子、亥、戌、酉、申、未、午、巳、辰、卯、寅
```

与太乙、天目、计神不同，现有卷三表没有同粒度的完整合神列。因此合神仍只作为“公式 + 首位例证”的机械候选，审计档案明确保留这一证据差异。

## 异文处理

1. Kanripo 卷一转录作“遇阴德大武重留一算”，Chinese Text Project 的不同检索结果曾同时出现“阴德”和“武德”。卷三表第 4/5 局连续阴德、第 17/18 局连续大武，后续每十八局重复，因此代码采用阴德，同时保存“武德”异文。
2. 卷二十六神身份目录作“太神”，卷三相同天目序位作“大神”。代码枚举名使用 `TaiShen`，中文规范显示“太神”，并通过 `received_table_variant` 保留“卷三立成表作大神”，不删除异文。
3. 这些规范化只服务于机械身份对齐，不判断哪个神吉凶，也不允许进入规则程序。

## 失败关闭边界

`taiyi_annual_frame_from_accumulated_count` 返回的审计对象永久标记以下状态为 `false`：

- 已选择积年历元；
- 由现代日期推得；
- 已选择阴阳遁；
- 已生成完整局式；
- 可解释、可生成中间信号或可成为规则输入。

尚未实现的相邻字段包括文昌、始击、主客算、定算、主客大小将、八门、掩击迫囚等。卷三表里出现这些列并不构成实现许可。

## 自动验证

- 前 24 局太乙、天目和计神表锚点；
- 太岁与合神的 1、2、12、13、60、61 算边界；
- 阴德、大武重留位置；
- 一至 720 算的 60/24/18/12 周期穷举；
- 零输入拒绝和 `u64` 最大值先约减后转换；
- 研究档案与 Rust 中文神名、干支、算法版本逐项对拍；
- 正式规则种子必须继续为空。

完整机器档案见 `data/research/taiyi-annual-frame-candidates.json`。在历元、影印校勘、剩余局式和解释规则分别通过门禁以前，太乙插件保持“仅排盘、不参与裁决”。
