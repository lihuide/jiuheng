# 离线乡镇街道地点库审计（v0.65.0）

## 来源与可复现生成

- 行政名称、九位代码、层级：`slightlee/regions-data` 的国家地名信息库 2025-12-31 快照，提交 `018603e0ef0124577807deb692a21040f9fcdd20`，MIT 许可。原始整理 JSON：<https://github.com/slightlee/regions-data/blob/018603e0ef0124577807deb692a21040f9fcdd20/data/processed/regions_20260304_173812.json>。
- 该 JSON 的 SHA-256：`d03463a39014b72e6b4cf093af8327e2539aa9efbb010c8d2eb59a054cb632fe`。内部 `meta.table_name` 为 `Xzqh20251231`，`is_partial=false`，共 41,935 条，其中乡级 38,723 条。
- 经纬度：既有 `data/locations.seed.json` 中 GeoNames CN 区县中心坐标，CC BY 4.0；该文件 SHA-256 为 `daf969babe5123db49bb5aec4c0c8005c9e812f30fe74ca8857b82e0bcca24b2`。行政名称源不提供经纬度，绝不把街道名称误标为街道中心坐标。
- 运行 `scripts/build-street-seed.py --source <下载的快照 JSON>` 可生成 `data/streets.seed.json`；该文件的 SHA-256 为 `a0d2c33e471a71f295c6342081e4cee9e20541782cca45353bce8ff505f4e6a3`。生成器首先核对两份输入的 SHA-256，再要求源记录完整、父级可追溯、坐标落在中国大陆合理范围及代码唯一。

## 匹配与拒绝口径

优先用省、市、区县名称三元组精确匹配现有 GeoNames 区县中心。三元组未匹配时，仅当“同省 + 同名区县”在 GeoNames 中恰好唯一，才允许匹配；保留匹配方式和 GeoNames ID。四级记录必须有三级区县父级。港澳台不纳入第一版大陆地点库。

| 结果 | 条数 |
|---|---:|
| 乡镇街道原始记录 | 38,723 |
| 省/市/区县完整精确匹配 | 32,562 |
| 同省同名区县唯一匹配 | 1,973 |
| 可选地点，统一标记“区县中心坐标” | 34,535（约 89.18%） |
| 找不到唯一区县中心，拒绝开放 | 4,086 |
| 缺少三级区县父级，拒绝开放 | 102 |

因此，本版**不是**全国街道坐标全覆盖，更不是街道中心、门牌地址或 GPS 数据库。未匹配的 4,188 条不会用城市中心或猜测坐标填补。界面允许搜索已开放的街道名称，并始终显示“天文计算仍使用区县中心近似坐标”。如果未来具备可靠街道中心坐标，须另建来源、精度和升级审计，不覆盖历史占问已锁定的坐标。

每条 SQLite 街道记录保存行政代码、完整名称、匹配方式、所借 GeoNames ID、来源快照、版本和组合许可证。旧占问的地点和经纬度属于锁定输入，不因地点库升级而改写。此项只改善参数输入，不放行任何古籍断法或 Rule ID。
