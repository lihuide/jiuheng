# 古籍规则准入流程

1. 建立书目记录：书名、时代、作者/传承、卷篇、底本、整理或影印来源。主来源必须有准确卷页与馆藏号；下载所得文件须记录字节数及规范小写 `sha256:` 校验和，并由开发者模式的 `jiuheng.sha256.v1` 或 `scripts/verify-source-facsimile.ps1` 对实际字节复核。正式数据库必须保存与当前版本一致的字节验证记录；只有校验和字段而没有实际验证记录时失败关闭。文件验证仍不能代替内容审校。
2. 逐字录入原文并保留异文，不从网络摘要反推规则。
3. 将原文拆成条件、对象、结果、应期和例外；无法闭合的句段标记为不稳定。
4. 比较同术式早期文献与后世注本。若冲突，保留证据链并停用冲突规则。
5. 研究中的候选原文只写入 `data/research`，必须标记 `executable_seed_eligible = false`，运行时不加载。
6. 分别完成书目、转录、逻辑、实现四类复核；复核记录绑定当前规则正文与证据包哈希。
7. 编写正例、反例、边界例和历史复盘测试；测试结果绑定当前规则、实现版本和测试套件哈希。
8. 只有 `实际影印字节验证 + 稳定 + 四类复核通过 + 当前测试套件零失败` 的规则，才可进入正式种子包并由门禁改为可参与。

## 开源参考实现附加门禁

开源项目只能作为机械结构和独立验证源，不能作为古籍证据。开始对拍前必须固定仓库 commit、Git tree、确定性归档哈希、所读文件哈希和许可证；参考项目更新后不得沿用旧结论。固定源码身份只允许静态审计，不能自动打开执行门。执行还必须闭合许可证、依赖锁、网络/AI 隔离和输入输出适配层。相同输入的逐字段结果必须记录一致、误差、分歧与边界，分歧不能用多数票解决，必须回到古籍影印本和独立天文/历法依据。

不得从参考项目复制断语、吉凶、用神、应期、行动建议、权重、AI 输出或现代评分。即使机械输出完全一致，也只能证明两个实现一致，不能证明规则正确；仍须完成九衡自己的书目、转录、逻辑、实现四类复核。项目清单、固定源哈希和未执行夹具分别见 `data/research/open-source-reference-implementations.json`、`data/research/reference-source-manifest.json` 与 `data/research/reference-crosscheck-fixtures.json`；首轮审计见 `docs/OPEN_SOURCE_REFERENCE_AUDIT.md`。

规则证据等级不参与日常加权，只在同权信号发生明确僵局时作为破局依据。
