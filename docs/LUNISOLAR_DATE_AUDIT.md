# 现代农历日期候选审计

## 结论边界

0.19.0 在冬至—中气月结构上新增“北京时间民用日 → 名义农历年、月、日”的机械候选。它可以输出月号、是否闰月、日序以及该月为 29 天或 30 天，并保存日期归属是否通过日界安全门。

算法版本固定为 `jiuheng.lunisolar_date.modern_official_civil_day.v1`，状态固定为 `modern_official_candidate_not_historical_calendar_or_divination_rule.v1`。

这是现代官方历法口径的工程审计，不是对历代中国历法的一套统一反推，也不是八字、紫微、七政四余或其他术式的年/月/日换界规则。任何边界不安全的候选都禁止驱动正式规则。

## 日期生成

1. 先按北京时间民用日选择实际覆盖目标日期的冬至月结构。
2. 在结构内寻找满足“本月初一民用日 ≤ 目标民用日 < 下月初一民用日”的月份。
3. 日序为目标民用日与本月初一的日数差加一。
4. 相邻两个朔日之差必须为 29 或 30；出现其他长度时失败关闭。
5. 正月开始的公历年份保存为名义农历年；正月之前的十一月、十二月归入前一名义年。

名义年只是便于核对现代历书的数值标签，不会自动生成生肖、干支年或任何术式年柱。

## 修正的周期边界

包含冬至的十一月通常早于冬至瞬间开始。旧的 0.18.0 选择器只用“目标日期是否已到冬至日”选择结构，因此冬至前但已经进入新十一月的几天可能选到上一周期。

0.19.0 改为实际计算当前年和前一年两个候选结构，并按月首民用日区间选择真正覆盖目标日期的结构。自动测试直接构造“十一月初一早于冬至日”的情形，防止这个错误回归。

## 安全状态

每个日期候选分别保存：

- 本月月首与下月月首是否远离北京时间午夜保护带；
- 整个冬至周期的朔、中气和冬至日界是否全部安全；
- 日期归属是否同时满足上述两级安全条件。

保护带继续包含月相或太阳算法误差、ΔT 估算误差、固定 300 秒边距和半秒反算舍入保护。候选即使与现代年历标签一致，只要完整周期存在边界不安全项，仍明确标记为不可驱动规则。

## 官方锚点与不变量

自动测试包含：

- 2024-02-10 → 名义 2024 年正月初一；
- 2024-02-24 → 正月十五；
- 2024-09-17 → 八月十五；
- 2023-03-22 → 闰二月初一；
- 2025-07-25 → 闰六月初一；
- 同一北京时间日期内的 `00:00:00` 与 `23:59:59` 必须得到同一月日；
- 所有成功候选的民用月长度只能为 29 或 30 天。

现代日期标签用香港天文台年历作独立锚点；这些资料只验证历法机械输出，不会登记为古籍断法证据。

## 快照兼容

天文快照升级为 v11，新增完整日期候选、算法与状态、月首/下月月首、月长及两级安全结论。结构成功但日期无法生成时保存独立错误；结构本身失败时不会伪造日期错误。

v1–v10 快照继续按原始 JSON 和 BLAKE3 哈希读取，不补算新字段、不改写历史值。开发者模式会用当前算法重新计算 v11 字段并逐项比较。

## 尚未完成

- 历代历法改革、历元和不同时期置闰制度尚未分朝代闭合；现代候选不能直接用于古代历史日期。
- 公元前 1000 年至公元 3000 年尚未完成独立星历与历书全范围交叉验证。
- 生肖、干支年换界和九术各自采用何种历法口径仍需分别通过古籍证据门禁。
- 没有任何术式获准用本候选产生排盘或断法信号。
