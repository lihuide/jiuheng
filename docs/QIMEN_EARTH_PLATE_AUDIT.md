# 奇门九宫与三奇六仪地盘机械候选审计

## 本版完成范围

0.28.0 在上一版阴阳遁、三元与局数候选之上增加：

`jiuheng.qimen.received_three_wonders_six_instruments_earth_plate.v1`

程序固定保存：

- 坎一、坤二、震三、巽四、中五、乾六、兑七、艮八、离九的九宫编号与八卦身份；
- 六甲分别隐于戊、己、庚、辛、壬、癸；
- 三奇为乙、丙、丁；
- 从局数本宫起按 `戊己庚辛壬癸丁丙乙` 排满九宫；
- 阳遁按宫数递增循环，阴遁按宫数递减循环；
- 北京时间零点换日与真太阳时零点换日两套地盘候选；
- 算法版本、完整性标志及全部禁止解释标志。

这一层只产生地盘，不产生天盘或占断。

## 文本依据与采用边界

北宋《景祐遁甲符应经》“六仪飞布图局”保存“阳遁九局，顺布六仪，逆布三奇；阴遁九局，逆布六仪，顺布三奇”的总则。《奇门遁甲统宗》卷二公共转录进一步给出：

- “左三右七，戴九履一，二四为肩，六八为足，五居中宫”；
- 顺为一至九、逆为九至一；
- 甲子、甲戌、甲申、甲午、甲辰、甲寅分别隐于戊、己、庚、辛、壬、癸；
- 阳一局与阴九局的完整三奇六仪宫位例。

《御定奇门遁甲宝鉴》公共转录提供相同两个完整例作为交叉线索。国家图书馆藏《奇门遁甲统宗》扫描件已经登记，但本轮仍未完成准确册页和逐字影像绑定。因此这些内容只进入机械研究候选，不形成正式 Rule ID。

详细来源和证据限制保存在：

`data/research/qimen-earth-plate-candidates.json`

## 九宫与布置算法

地盘记录始终按宫数一至九排序，而不是按飞布过程排序：

```text
一  坎      二  坤      三  震
四  巽      五  中      六  乾
七  兑      八  艮      九  离
```

程序内部以局数本宫作为戊的起点，然后布置：

```text
戊 → 己 → 庚 → 辛 → 壬 → 癸 → 丁 → 丙 → 乙
```

- 阳遁：宫数每次加一，九后回一；
- 阴遁：宫数每次减一，一前回九。

两个完整锚点为：

```text
阳遁一局，按一至九读取：戊 己 庚 辛 壬 癸 丁 丙 乙
阴遁九局，按一至九读取：乙 丙 丁 癸 壬 辛 庚 己 戊
```

自动测试遍历阴阳二遁各九局，要求每盘九宫编号唯一、九个干恰各出现一次、戊恒在局数本宫，并核对六仪隐甲关系。局数不是一至九时直接报错。

## 与上一层的失败关闭关系

地盘必须由一个已生成的局数候选派生。上一层若因处暑异文而没有局数，本层的 `earth_plate` 必须为 `null`。如果日界或节气交接处在安全边距内，程序仍可保存用于审计的机械候选，但父候选的 `mechanical_boundaries_safe` 为 `false`，不得驱动任何规则。

北京时间与真太阳时日界可能得到不同符头、三元、局数和地盘，两套结果继续并列，不自动选择。即使两套结果相同，也不能据此宣布传统日界争议已经解决。

## 明确没有实现

0.28.0 没有实现：

- 超神、接气、置闰、拆补等历法口径选择；
- 时旬首、值符、值使及其逐时转动；
- 天盘三奇六仪；
- 九星、八门、八神；
- 中五寄坤、寄艮或其他寄宫流派选择；
- 格局、用神、吉凶、应期、中间信号或综合裁决。

地盘对象中的 `interpretation_eligible` 和 `rule_eligible` 恒为 `false`。正式规则种子仍为零条。

## 快照与兼容

顶层天文审计快照从 v18 升级到 v19，奇门审计对象从 v1 升级到 v2。v18 历史记录中的两个日界候选没有 `earth_plate` 字段，反序列化时保持为空；程序不会为旧记录补造地盘或改变原始 JSON 哈希。

开发者模式显示两套地盘，并在 v19 记录中做完整逐字段重算比较。对 v18 记录只比较当时已经存在的局数候选字段，避免新版本地盘字段让旧快照无条件报错，同时仍能发现旧局数数据被修改。
