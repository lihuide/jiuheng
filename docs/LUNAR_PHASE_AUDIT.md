# 朔望月天文基础审计

## 本版结论

0.17.0 新增的是天文相位基础，不是完整中国农历。核心可以计算版本化的朔、望 TT 时刻，并返回包围任意占问时刻的“上一朔 → 本月望 → 下一朔”区间。它不会据此生成农历年月日、月序、闰月、命盘或占断信号。

香港天文台对中国农历的公开说明把朔定义为日月在黄道上同经，并说明农历月从朔开始；其月相表采用英国皇家航海历书局及美国海军天文台提供的数据，时间为 UTC+8。项目只把这些官方数据作为独立数值锚点，不把网页解释转换为术数规则。

## 算法和版本

- 相位算法：`jiuheng.lunar_phase.meeus_true_phase.v1`
- 朔望月区间：`jiuheng.lunation_interval.true_new_moon.v1`
- 时间尺度：相位结果为 `JD(TT)`，与现有 ΔT/TT 层对齐。
- 计算内容：J2000 平朔纪元、朔望月长度、多项式项、日月平近点角、月球纬度幅角、升交点以及周期改正项。
- 支持范围：应用输入仍限定为公元前 1000 年（天文年 -999）至公元 3000 年；相位内部额外保留搜索边距，便于年界附近求下一朔。

实现不依赖网络、API 或内置大星历。所有系数固化于 Rust 核心，给定同一 TT 和算法版本会得到完全相同的结果。

## 误差与失败关闭

本版给每个相位事件保存保守公式误差：

| 距 J2000 | 保存的公式误差 |
|---|---:|
| 100 年内 | ±120 秒 |
| 100–500 年 | ±600 秒 |
| 500–1500 年 | ±1800 秒 |
| 更远年代 | ±3600 秒 |

这些数值是工程安全预算，不是对全部年代的独立精度认证。朔界安全判断还会额外加入 300 秒边距；占问时刻落入“公式误差 + 安全边距”时，状态为边界不安全，后续历法规则不得使用该结果决定月界。

## 独立锚点

自动测试采用香港天文台年历的 UTC+8 分钟值：

| 相位 | 官方时刻（北京时间） | 自动测试容差 |
|---|---|---:|
| 朔 | 2024-01-11 19:57 | 120 秒 |
| 望 | 2024-01-26 01:54 | 120 秒 |
| 朔 | 2024-08-04 19:13 | 120 秒 |
| 望 | 2024-08-20 02:26 | 120 秒 |
| 望 | 2024-09-18 10:34 | 120 秒 |
| 朔 | 2026-01-19 03:52 | 120 秒 |

测试同时覆盖：上一朔、望、下一朔的严格顺序，精确朔界必须判为不安全，非有限输入、负安全边距和越界日期必须失败关闭。

## 快照与兼容

天文快照升级为 v9，新增一个完整 `LunationInterval`：

- 上一朔、本月望、下一朔的相位、朔望月序号、`JD(TT)`、公式误差和算法版本；
- 距上一朔和下一朔的秒数；
- 额外安全边距与朔界安全状态；
- 固定状态 `astronomical_phase_audit_not_chinese_calendar.v1`。

快照仍以原始 JSON 字节的 BLAKE3 哈希校验并禁止覆盖。v1–v8 历史快照缺少本字段时保持 `None`，不会用新算法补造历史结果。

## 尚未完成

- 未实现精密月球位置接口和任意时刻的月球黄经、黄纬、距离。
- 0.18.0 已另建冬至—中气月结构，0.19.0 又新增现代年月日候选；历史历法制度差异、生肖与术式换界仍未闭合。
- 未完成公元前 1000 年至公元 3000 年的跨年代独立星历验证。
- 未允许任何术式规则使用朔望结果。

在上述工作闭合前，桌面开发者模式会明确显示“仅天文相位，不是农历日期或置闰结果”。
