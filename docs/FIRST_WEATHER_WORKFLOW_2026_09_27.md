## 为什么不能直接写“父母动就下雨”

电子转录中的天气段同时涉及父财、应爻空亡、合住与冲开、动变、三合、旺衰及应期。它足以说明不能把单句口诀当完整程序，但尚不足以证明这些文字的版本和完整释义。

| 必须闭合的条件 | 现有程序能提供 | 仍然缺少 |
|---|---|---|
| 父母、妻财与动静 | 六亲身份、实际动爻 | 兴隆/衰弱定义、制约条件、多个相关爻的选择 |
| 空亡、冲合 | 未配支身份、支对关系 | 空亡生效、合住/冲开生效条件及规则优先关系 |
| 动变、三合 | 实际变支、三合成员原始清点 | 变爻效力、成局条件、父财同动及相反信号的处理 |
| 应期 | 北京时间、目标范围、日时标签 | 原典应期及适用边界；不能随意改成“1小时/3小时” |
| 当下怎么做 | 建议的数据结构与来源绑定 | 经过审查的建议依据；天气占辞不能自动变成行动建议 |

不得为了第一个演示结果，省略异常盘或给未覆盖的占问强行断晴雨。时间无依据时显示“暂无法断定”；建议无依据时不冒充古法建议。

## 首条流程的验收条件

1. 实际读取影印原件、固定版本与哈希，定位完整天时章节及依赖基础章。
2. 逐字核对原文、注释与异文；比较可用早期材料，遇到冲突或含义不稳的条件停止启用。
3. 明确适用的问题范围、全部前提、例外、相反规则和应期。每个程序条件有出处，不从开源项目抄断语。
4. 按书目、转录、逻辑、实现四类分别记录真实复核；正例、反例、边界、无适用和冲突例均自动验证。
5. 桌面实际走通锁题 → 三币六次 → 适用性 → 已放行规则 → 结论/时间/依据等级/有据建议 → 本地保存 → 历史重放。
6. 重新构建 Windows，检查新旧记录兼容、隔离安装启动及离线运行。只有以上条件闭合，才报告首条流程完成；这仍不等于九术全部完成。
